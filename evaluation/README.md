# Evaluation

This directory provides the evaluation workflow for SemQueryBench. It is used to evaluate prediction files generated by user methods or reproduced baselines.

The evaluation pipeline computes three instance-level outputs:

- **Execute Match (EM)**: whether the predicted SQL execution result matches the gold SQL result under the SemQueryBench result-containment rule.
- **Effective Match (EffM)**: whether the predicted SQL correctly answers the user question, judged by an LLM after confirming that the SQL is executable.
- **Diff desc**: a natural-language description of the main difference between the gold SQL and the predicted SQL.

The test set does not release gold SQL. Local evaluation is therefore supported for the dev set only. Test-set evaluation should be performed by the benchmark maintainers or an evaluation server with access to hidden gold SQL.

## Submission Format

Prediction files should be submitted as JSON lists. Each item corresponds to one prediction from one model and one method on one benchmark instance.

### Dev submission

Dev submissions may contain `Gold-sql`, because dev evaluation is intended to be reproducible locally.

Required fields:

```json
[
  {
    "Level": "easy",
    "id": "72",
    "db_id": "IDC",
    "question": "In image data sharing platforms (IDC), which raw datasets have the largest number of samples? The top five listed companies.",
    "Gold-sql": "SELECT collection_name FROM IDC.IDC_V17_ORIGINAL_COLLECTIONS_METADATA ORDER BY Subjects DESC LIMIT 5;",
    "model": "qwen-72b",
    "method": "MCS",
    "pred-sql": "SELECT collection_name, Subjects FROM IDC.IDC_V17_ORIGINAL_COLLECTIONS_METADATA ORDER BY Subjects DESC LIMIT 5;"
  }
]
```

### Test submission

Test submissions must not contain `Gold-sql`.

Required fields:

```json
[
  {
    "Level": "easy",
    "id": "72",
    "db_id": "IDC",
    "question": "In image data sharing platforms (IDC), which raw datasets have the largest number of samples? The top five listed companies.",
    "model": "qwen-72b",
    "method": "MCS",
    "pred-sql": "SELECT collection_name, Subjects FROM IDC.IDC_V17_ORIGINAL_COLLECTIONS_METADATA ORDER BY Subjects DESC LIMIT 5;"
  }
]
```

Do not include SQA identifiers, SQA templates, skeleton IDs, template IDs, anchor mappings, slot mappings, API keys, passwords, private endpoints, or local absolute paths in submission files.

## Environment Configuration

Create a local `.env` file from the example:

```powershell
copy evaluation\configs\.env.example evaluation\configs\.env
```

Edit `evaluation/configs/.env` with local credentials:

```text
# MySQL
SEMQUERY_MYSQL_HOST=localhost
SEMQUERY_MYSQL_PORT=3306
SEMQUERY_MYSQL_USER=root
SEMQUERY_MYSQL_PASSWORD=your_mysql_password

# LLM judge
SEMQUERY_LLM_API_KEY=your_api_key
SEMQUERY_LLM_BASE_URL=https://.../v1
SEMQUERY_LLM_MODEL_EFF=deepseek-v4-pro
SEMQUERY_LLM_MODEL_DIFF=deepseek-v4-pro
```

The `.env` file is for local use only and must not be committed. Only `.env.example` should be tracked.

## Step 1: Execute SQL

Run:

```powershell
python evaluation/scripts/execute_sql_results.py `
  --input evaluation/submission/dev_submission_example.json `
  --output evaluation/submission/outputs/dev_executed.json
```

This script executes both gold SQL and predicted SQL against the corresponding MySQL database.

It appends the following fields:

```text
gold_exec_status
gold_result
gold_result_len
gold_exec_error
pred_exec_status
pred_result
pred_result_len
pred_exec_error
```

A predicted SQL is treated as invalid if it does not contain both `SELECT` and `FROM`. This is because SemQueryBench SQL queries are database-grounded selection queries.

This script does not compute EM, EffM, or diff descriptions. It only executes SQL and records execution results.

## Step 2: Compute Execute Match, Effective Match, and Diff desc

Run:

```powershell
python evaluation/scripts/compare_sql_results.py `
  --input evaluation/submission/outputs/dev_executed.json `
  --output evaluation/submission/outputs/dev_compared.json
```

### Execute Match

Execute Match is computed deterministically from SQL execution results.

A prediction receives `Execute Match = 1` if:

- the gold SQL executes successfully;
- the predicted SQL executes successfully;
- the predicted result has the same number of rows as the gold result;
- every value in each gold row is contained in a predicted row;
- predicted rows may contain extra columns;
- column names are ignored;
- if the gold SQL contains `ORDER BY`, row order is respected; otherwise rows are matched without order.

This means that selecting extra columns is allowed if all gold values are present and the row count is unchanged. For example, if the gold SQL returns only `name` and the predicted SQL returns `id, name`, it may still receive `Execute Match = 1`.

### Effective Match

Effective Match is judged by an LLM. The prerequisite is that the predicted SQL must execute successfully.

The criterion is whether the predicted SQL answers the user question, not whether it follows the same reasoning path as the gold SQL. A semantically valid alternative query can receive `Effective Match = 1` even if its SQL structure differs from the gold SQL.

### Diff desc

`Diff desc` is a natural-language description of the main SQL-level difference between gold SQL and predicted SQL. It is generated by an LLM using `evaluation/prompts/compare_two_sql.md`.

To test only Execute Match without calling the LLM, run:

```powershell
python evaluation/scripts/compare_sql_results.py `
  --input evaluation/submission/outputs/dev_executed.json `
  --output evaluation/submission/outputs/dev_compared.json `
  --skip-effm `
  --skip-diff
```

## Step 3: Aggregate Scores

Run:

```powershell
python evaluation/scripts/aggregate_scores.py `
  --input evaluation/submission/outputs/dev_compared.json `
  --output evaluation/submission/outputs/dev_summary.csv
```

The summary file reports aggregated scores by tier, model, and method:

```text
Level
model
method
n
EM
EffM
```

where:

- `EM` is the mean of `Execute Match`;
- `EffM` is the mean of `Effective Match`;
- `n` is the number of evaluated instances.

## Output Files

The standard output files are:

```text
evaluation/submission/outputs/dev_executed.json
evaluation/submission/outputs/dev_compared.json
evaluation/submission/outputs/dev_summary.csv
```

These files are local evaluation outputs. They can be regenerated from a dev submission file and the evaluation scripts.

## Test Evaluation

Public test files do not include `Gold-sql`. Therefore, users cannot compute test EM or EffM locally unless they have access to hidden gold SQL.

The intended test workflow is:

```text
user test submission
→ hidden gold SQL added by maintainers/evaluation server
→ execute_sql_results.py
→ compare_sql_results.py
→ aggregate_scores.py
→ official test scores
```

## Security and Release Notes

Do not commit:

```text
evaluation/configs/.env
evaluation/submission/outputs/
files containing API keys
files containing MySQL passwords
files containing private endpoints
files containing local absolute paths
files containing hidden gold SQL for test
files containing SQA templates, skeleton IDs, anchor mappings, or slot mappings
```

Recommended `.gitignore` entries:

```gitignore
evaluation/configs/.env
evaluation/submission/outputs/
```
