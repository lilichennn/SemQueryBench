# Result File Format

SemQueryBench result files should be organized in **long format** for scripts and optional **wide format** for manual inspection.

## Recommended Long Format

Each row corresponds to one prediction from one model and one baseline method on one benchmark instance.

Required columns:

| Column | Description |
|---|---|
| `Level` | Difficulty tier: `easy`, `medium`/`mid`, or `hard`. |
| `id` | Question/sample identifier. |
| `db_id` | Database identifier. |
| `model` | LLM name, e.g., `qwen-72b`. |
| `method` | Baseline method, e.g., `MCS`, `Opensearch`, `DAIL-SQL`, `SDK`. |
| `pred-sql` | Predicted SQL generated by the method. |

Optional columns:

| Column | Description |
|---|---|
| `question` | Natural-language question. |
| `Gold-sql` | Gold SQL. Allowed in dev files only. Must be omitted from public test files. |
| `Execute Acc` | EM / execution-match label: `1` or `0`. |
| `Efficient Acc` | EffM label: `1` or `0`. |
| `diff desc` | Natural-language SQL difference description. |

## Dev File

Dev files may include `Gold-sql`, because they are used to demonstrate the evaluation pipeline.

Example:

```text
Level | id | db_id | question | Gold-sql | model | method | pred-sql | Execute Acc | Efficient Acc | diff desc
```

## Public Test File

Public test files must not include `Gold-sql`, `Gold-DATA`, `Gold-DATA-LEN`, SQA IDs, template IDs, anchor mappings, or slot mappings.

Example:

```text
Level | id | db_id | question | model | method | pred-sql | Execute Acc | Efficient Acc | diff desc
```

## Do Not Release

Do not include the following in public result files:

```text
Gold-sql in test files
Gold-DATA
Gold-DATA-LEN
pred-data
pred-data-len
sqa
sqa_id
template_id
anchor mapping
slot mapping
API keys
passwords
private endpoints
local absolute paths
```
